# AR-0103 Local bridge implementations and conformance

Implement runtime bridge adapters for local Coordinator/AWC, AWQ, AWG, and UI instances behind the AR-0102 contracts. “Live” means actual request/event exchange with those local authority processes, not canned responses; bridges remain provider-neutral and use explicit capability negotiation. Enforce revision and lease fencing, bounded deadlines, cancellation, idempotency, redaction, fail-closed unknown outcomes, and authority-owned mutation boundaries. Provide deterministic in-process/local-process fixtures and conformance tests for positive flows and malformed, stale, unavailable, slow, duplicate, replayed, and unauthorized responses. A UI decision must be an authenticated, validated UI-owned event; worker/LLM text cannot substitute. Do not require a network service, hosted account, model, or live provider.

## Acceptance evidence

- Versioned contract or implementation artifacts with exact source revision and reproducible local commands.
- Positive and hostile checks for the failure and authority boundaries in scope.
- Offline operation demonstrated; provider/backend access remains optional and absent from mandatory acceptance.
- Limitations and unsupported cases stated explicitly; no readiness claim based only on configuration or unit tests.
