# AR-0098 formal authority interaction and mandatory-gate model

Build a finite-state, revision-bound model whose state is partitioned by authority:

- AWC/Coordinator owns task identity, revision, dependency state, claims, leases, and terminal commits.
- AWR owns bounded scheduling, supervision, transport, enforcement, retry mechanics, and evidence projection; it cannot approve.
- AWQ owns requirements, evidence policy, quality evaluation, and acceptance/rejection/unknown outcomes.
- AWG owns oracle-discussion admission, decisions, and reusable guidance; AWR cannot infer or manufacture them.

Define transitions and temporal properties for one and many concurrent jobs. Required safety properties include exact binding, single fenced owner, no execution before AWC admission, no continuation before AWQ acceptance, mandatory AWG resolution for material uncertainty, no completion before AWC commit, and no state change from stale/replayed/crossed results. Required liveness properties are conditional: when all authoritative responses arrive, leases remain valid, and resources are available, an admitted job eventually reaches an explicit terminal state; otherwise it remains blocked or pending.

Treat absent, malformed, contradictory, delayed, or ambiguous LLM/agent output as untrusted data. It must produce `blocked`, `pending`, or `unknown`, never approval. Implement a small deterministic model checker and trace reducer in the runtime repository, with positive traces, every single-edge omission, concurrent interleavings, crash/recovery traces, and refinement checks against the executable scheduler/contractor events. The model is local-only and requires no service, provider, network, or LLM.
