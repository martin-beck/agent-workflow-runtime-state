# AR-0098 formal authority interaction and mandatory-gate model

Build a finite-state, revision-bound model whose state is partitioned by authority:

- AWC/Coordinator owns task identity, revision, dependency state, claims, leases, and terminal commits.
- AWR owns bounded scheduling, supervision, transport, enforcement, retry mechanics, and evidence projection; it cannot approve.
- AWQ owns requirements, evidence policy, quality evaluation, and acceptance/rejection/unknown outcomes.
- AWG owns oracle-discussion admission, decisions, and reusable guidance; AWR cannot infer or manufacture them.
- Agent Workflow UI owns the validated decision interface and human decision events; rendering, worker text, or an LLM output is never a decision.

Define transitions and temporal properties for one and many concurrent jobs. Required safety properties include exact binding, single fenced owner, no execution before AWC admission, no continuation before AWQ acceptance, mandatory AWG resolution for material uncertainty, no completion before AWC commit, and no state change from stale/replayed/crossed results. Add mandatory change-control properties: a worker or runtime may propose but never directly mutate a user decision, test, or specification; any required change/refinement must pass through an AWG decision request, a validated decision-interface/UI event, and the owning authority's revision-fenced commit. If an autonomous worker is blocked, bounded repair workers must be attempted under the same contract; if they cannot resolve the block, AWR must emit an AWG escalation and obtain a decision-interface/UI outcome. Missing, refused, expired, or ambiguous decisions keep the work blocked. Required liveness properties are conditional: when all authoritative responses arrive, leases remain valid, and resources are available, an admitted job eventually reaches an explicit terminal state; otherwise it remains blocked or pending.

Treat absent, malformed, contradictory, delayed, or ambiguous LLM/agent output as untrusted data. It must produce `blocked`, `pending`, or `unknown`, never approval. Implement a small deterministic model checker and trace reducer in the runtime repository, with positive traces, every single-edge omission, concurrent interleavings, crash/recovery traces, direct-worker-mutation attempts, skipped-AWG/UI decision attempts, unresolvable repair escalation, and refinement checks against the executable scheduler/contractor events. The model is local-only and requires no service, provider, network, or LLM.
