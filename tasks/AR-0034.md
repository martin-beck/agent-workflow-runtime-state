# AR-0034: OpenCode live provider adapter

## Objective

Implement and qualify live OpenCode-compatible process/session execution through the normalized runtime contract.

This AR is a live-integration boundary. Define a versioned machine-readable specification and an offline checker first, then implement the smallest live path behind explicit authority, credential, network, and human-approval gates. Offline tests must remain runnable without provider or LLM access.

## Authority and integration

Coordinator remains authoritative for task identity, dependencies, claims, revisions, leases, and durable state. AWQ remains authoritative for requirements, quality gates, adapters, and evidence acceptance. AWG remains authoritative for uncertainty classification, oracle escalation, decisions, and reusable guidance. The UI remains authoritative for human-facing rendering and validated input. AWR owns only translation, execution, supervision, isolation, and integration boundaries.

## Required work

- Define the normative contract, state machine, schemas, bindings, errors, compatibility rules, and failure semantics.
- Add an autonomous positive/negative checker with stale revision, malformed input, replay, interruption, privacy, and unauthorized cases applicable to this boundary.
- Separate offline qualification from live evidence; record exact task revision, project revision, worktree, session, tool versions, and safe evidence.
- Make every live operation bounded, observable, cancellable, least-privileged, and fail closed; never expose credentials, prompts, transcripts, private paths, host identifiers, or raw output.
- Add a controlled integration fixture or harness and document exactly what remains unverified when live infrastructure is unavailable.

## Acceptance

The specification is versioned and machine-checkable; offline tests pass without external services; live behavior is gated and reproducible where enabled; authority boundaries are explicit; evidence is privacy-safe and revision-bound; failure and recovery are tested; and the AR leaves concrete follow-up work for any unresolved limitation.

## Dependencies

AR-0032

## Non-goals

Do not transfer authority from Coordinator, AWQ, AWG, or UI into AWR; do not treat a local green test or unverified remote observation as success; do not enable unbounded provider, network, publication, or durable-state mutation.

## Next action

Implement only after the specification admission and applicable AWQ/AWG review gates are satisfied. If alternatives materially affect downstream interfaces, create an AWG decision batch before implementation.
