# AR-0106 Multi-project operation

Support discovery, selection, scheduling, status, and lifecycle operations across multiple projects with strict project identity and state isolation. Each action must resolve an explicit project binding; prevent cross-project task IDs, leases, evidence, credentials, logs, caches, and UI decisions from bleeding between projects. Define concurrency and resource limits, project removal/archive behavior, and recovery when one project is unavailable. Extend deterministic local workflows to at least two projects with colliding task identifiers and concurrent events; hostile tests must attempt path escape, wrong-project callbacks, stale binding, and state contamination. Keep per-project authority boundaries intact and all integrations usable in offline/provider-free mode.

## Acceptance evidence

- Versioned contract or implementation artifacts with exact source revision and reproducible local commands.
- Positive and hostile checks for the failure and authority boundaries in scope.
- Offline operation demonstrated; provider/backend access remains optional and absent from mandatory acceptance.
- Limitations and unsupported cases stated explicitly; no readiness claim based only on configuration or unit tests.
