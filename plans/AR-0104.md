# AR-0104 New-project bootstrap

Provide an idempotent new-project command and documented workflow that creates the minimal project/state structure, binds product and state repositories, initializes Coordinator-compatible task/plan conventions, and registers the project with the runtime/umbrella where explicitly requested. Offer a safe preview and clear ownership choices for paths; validate empty/nonempty directories and existing bindings before mutation; preserve user content and refuse ambiguous ownership. Include a complete local-only sample project, machine-checkable schema and path validation, positive repeatability checks, and hostile checks for collisions, symlinks/escape paths, malformed metadata, and partial failure recovery. Bootstrap must not provision credentials or contact any provider/backend.

## Acceptance evidence

- Versioned contract or implementation artifacts with exact source revision and reproducible local commands.
- Positive and hostile checks for the failure and authority boundaries in scope.
- Offline operation demonstrated; provider/backend access remains optional and absent from mandatory acceptance.
- Limitations and unsupported cases stated explicitly; no readiness claim based only on configuration or unit tests.
