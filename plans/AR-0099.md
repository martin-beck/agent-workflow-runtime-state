# AR-0099 TLA+ formal authority and workflow gate model

Create a versioned TLA+ module and TLC configuration under the runtime repository. Keep the state space bounded and deterministic enough for CI while checking multiple concurrent jobs, lease/revision fencing, authority ownership, crash/recovery, retries, stale or replayed events, and terminal commit.

The specification must make these obligations explicit:

- AWC/Coordinator admission, current revision, lease, recovery, and terminal commit cannot be performed by AWR or an autonomous worker.
- AWR may schedule, execute, project evidence, retry, and request escalation, but cannot accept quality, approve guidance, or mutate a user decision, test, or specification.
- AWQ acceptance is required before continuation or completion.
- Material alternatives and every required refinement/change to a user decision, test, or specification must pass through AWG and, where a user decision is required, the validated Agent Workflow UI decision interface.
- When bounded repair workers cannot resolve a blocked worker, the job must escalate through AWG/UI and remain blocked or pending until a valid outcome.
- Missing, malformed, stale, replayed, contradictory, ambiguous, or expired results never become approval.

Add TLC safety and bounded conditional-liveness checks, negative traces for each omitted gate, positive concurrent traces, refinement assertions against the AR-0098 Python event model, and a CI command that fails when TLC is unavailable rather than silently skipping the formal check. Use a repository-pinned/local tool path or an explicitly documented preinstalled tool; do not use external services or live AI providers. Record model limits and any state-space reduction in the evidence fixture.
